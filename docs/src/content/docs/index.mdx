## A Taste of SPL (`.splx`)

```splx
import llm from "std/llm"
import os from "std/os"

/// Developer doc-comment (shown in IDE hover, omitted from LLM schemas).
'' Historical figure profile returned by the model.
type Person = struct {
    firstName: Str  '' Given name, e.g. Ada
    lastName: Str   '' Family name, e.g. Lovelace
    age: Int        '' Age in years
    profession: Str '' Primary occupation
}

let api_key = os.env("OPENAI_API_KEY") ?? panic("OPENAI_API_KEY not set")

// Automatically sends `type_schema<Person>()` and validates the JSON response!
let ada = llm.ask<Person>(
    provider: "openai_responses",
    model: "gpt-6-luna",
    api_key: api_key
) @{
    Generate a profile for Ada Lovelace.
}?

print("${ada.firstName} ${ada.lastName} (${ada.age}) — ${ada.profession}")
```

## Why SPL?

<CardGrid stagger>
  <Card title="First-Class Prompts & Schemas" icon="rocket">
    Write auto-dedented, brace-balanced <code>@&#123; ... &#125;</code> prompts with <code>$&#123;expr&#125;</code> interpolation, attach <code>''</code> LLM hints directly to fields, and generate JSON Schemas + decoders at compile time via <code>type_schema&lt;T&gt;()</code> and <code>decode&lt;T&gt;()</code>.
  </Card>
  <Card title="Hindley-Milner + Row Polymorphism" icon="approve-check">
    Zero <code>null</code> or <code>undefined</code>. Structural records, functional spread (<code>&#123; ...x, k: v &#125;</code>), open records (<code>..r</code>), hybrid dynamic records (<code>..extra: Dict&lt;Str, Json&gt;</code>), and exhaustive <code>match</code>.
  </Card>
  <Card title="Colorless Async & Agents" icon="seti:clock">
    No <code>async</code>/<code>await</code> clutter. The compiler infers suspension automatically, runs <code>map</code> sequentially to prevent runaway fan-out, and offers opt-in <code>par_map</code>, multi-provider <code>std/llm</code>, and deterministic <code>agent_replay&lt;T&gt;</code>.
  </Card>
  <Card title="Compiles to Clean ESM" icon="laptop">
    Targets Browser and Node 22+ / Bun / Deno with zero root runtime dependencies, self-tail-call optimization, reifiable generics (<code>reified fn</code>), and a built-in LSP server for VS Code.
  </Card>
</CardGrid>
