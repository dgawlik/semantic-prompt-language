## Why SPL?

<CardGrid stagger>
  <Card title="First-Class Prompts & Schemas" icon="rocket">
    Write auto-dedented, brace-balanced <code>@&#123; ... &#125;</code> prompts with <code>$&#123;expr&#125;</code> interpolation, attach <code>''</code> LLM hints directly to fields, and generate JSON Schemas + decoders at compile time via <code>type_schema&lt;T&gt;()</code> and <code>decode&lt;T&gt;()</code>.
  </Card>
  <Card title="Hindley-Milner, Rows & Nominal Newtypes" icon="approve-check">
    Zero <code>null</code> or <code>undefined</code>. Structural records, open records (<code>..r</code>), hybrid dynamic records (<code>..extra: Dict&lt;Str, Json&gt;</code>), zero-overhead nominal <code>newtype</code>s, type-level &amp; runtime <code>typeof</code>, and exhaustive <code>match</code>.
  </Card>
  <Card title="Colorless Async & Agents" icon="seti:clock">
    No <code>async</code>/<code>await</code> clutter. The compiler infers suspension automatically, runs <code>map</code> sequentially to prevent runaway fan-out, and offers opt-in <code>par_map</code>, multi-provider <code>std/llm</code>, and deterministic <code>agent_replay&lt;T&gt;</code>.
  </Card>
  <Card title="Clean ESM & Built-In CLI Tooling" icon="laptop">
    Targets Browser and Node 22+ / Bun / Deno with zero runtime dependencies, self-tail-call optimization, universal reified generics, interactive <code>spl debug</code> &amp; <code>spl trace</code> TUIs, and a built-in LSP server for VS Code.
  </Card>
</CardGrid>
