Natural language & models

Blockquotes let you write a step in plain language; ask, think and agent call the model from code. This page covers both, and how to check what comes back.

Blockquotes#

A blockquote is an agent command, not code to compile into SPL. The model sees the instruction, visible bindings and function signatures, active guidance and restrictions, and the available tools. It acts directly on the shared document scope through tool calls.

For a simple generation task, the comparable code is:

Blockquotes have these tools in addition to configured MCP tools:

Tool Purpose
load_variable(name) Read a shared variable or read-only $args; declared types return their complete JSON Schema
save_variable(name, value, schema?) Create or update a shared value; optionally use a declared type/schema name or inline JSON Schema
call_function(name, args) Invoke an existing SPL function or builtin with positional JSON arguments
get_env(name) Read one read-only environment value; missing values return null
ask_human(question) Ask for human input and return the answer directly
read_file, write_file, web_fetch, web_search, shell Use the existing exact runtime tools
restrict(kind, value) Narrow restrictions for the rest of the command, including function and MCP calls
set_guidance(kind, text) Add enforce/forbid guidance for this command and its nested model calls
success(value), fail(reason) End the whole document

These shared-scope tools are specific to blockquotes. Explicit agent expressions retain their existing runtime/MCP tool set; ask and think still have no tools.

call_function decodes JSON arguments against parameter annotations, including nested lists and records. For example, JSON 15 becomes an SPL int for a parameter declared n: int; unannotated parameters keep ordinary dynamic values. save_variable also decodes against an existing binding's type annotation. This does not relax validation of ordinary SPL values: numeric strings, fractional integers, invalid shapes, and ambiguous decoding targets still fail. Tool arguments are already parsed JSON, so integer values outside JavaScript's safe integer range are rejected when decoding to int, rather than risking a rounded value. Numeric unions interpret integral parsed numbers as int and fractional numbers or negative zero as float; the original decimal/exponent spelling is no longer available at this boundary.

For @validate[Review], the agent can inspect Review with load_variable("Review"). The returned schema includes nested fields, lists, and enums; <type Review> in the shared bindings overview is only a display label. The agent then saves with save_variable(name="review", value=..., schema="Review"). The runtime resolves the declared type, validates and decodes the JSON, and hydrates any opted-in classes, including nested ones. Structs and typed containers retain their contracts; constructor-only classes are rejected. An inline JSON Schema object or boolean, or the name of a binding holding one, keeps the existing validation-only behavior without class hydration. Invalid values fail before saving.

@name marks a binding or operation (@notes, @success, @read_file), not text substitution. Plain language works too. Common conventions guide the agent's tool choices:

Marker Agent behavior
@ENFORCE text / @FORBID text Follow prompt guidance; use set_guidance for nested model calls
@RESTRICT fs['./src'] exec['git'] Narrow the command's restrictions with restrict
@validate[Schema] Inspect Schema, then pass its name to save_variable for validation and typed decoding; invalid values stop the command
@HUMAN question Call ask_human; the shell prompts or consumes the next --human answer
@SUCCESS, @fail End the document

For a list or union schema, declare a named alias first, such as type Reviews = list[Review], and use @validate[Reviews]. The tool resolves binding names, not type-expression strings such as "list[Review]".

Each runtime tool call executes immediately in the interpreter and returns its real result to the same agent session. Tools run sequentially, not through a deferred action queue. Saving a variable takes effect immediately; prose replies do not create bindings. Functions retain their normal lexical scope and runtime guards. Any runtime or MCP tool error stops the command immediately, preserving the original failure. The model cannot continue or retry after a failed action; completed external actions are not repeated. Follow important steps with an spl check:

--check validates syntax only; it cannot validate a blockquote's intent. --trace records the agent's decisions and runtime tool results. Replay restores shared-variable changes and function execution without repeating external effects or contacting MCP. Reuse the same --trace path to resume or replay; choose another JSONL file to restart. Run only trusted documents. Old traces containing submitted SPL are incompatible with agent commands; record a new trace.

Human input prompts directly in the shell and returns the answer to the same agent session. Repeat --human <answer> to answer questions in order without prompting. With --trace, completed decisions, effects and human answers replay from the same file, then the agent continues with any new answers. Supplied answers are consumed only for questions not already recorded. See Human input.

Generation: ask and think#

ask prompt returns the model's answer as a value. think is the same with medium reasoning by default. Neither has tools: they cannot read files, browse or run commands.

Each call starts a fresh session. Pass context explicitly, usually through interpolation.

Model responses stream into the interactive CLI view and notebook cell outputs while the model is working, including available reasoning by default. hide=True suppresses reasoning, not responses. These are previews: variables, JSON parsing, schema validation and repairs use the completed response, never partial chunks. Failures and cancelled turns do not turn partial output into a successful result. Traces and recordings retain complete responses rather than streaming chunks; replay does not manufacture token timing.

Embedded integrations can use LoggerOptions.streamSink for request-scoped ModelStreamEvent updates and completion/failure notifications. Backend callers can supply LlmRequest.onStream. Updates identify a response or reasoning channel and an SDK message ID: append chunks with mode: 'append', replace content with mode: 'replace', and reset the preview when the message ID changes. Ordinary event/string sinks still receive complete transcripts; LlmResponse.text is always the authoritative return value.

Agents#

agent prompt lets the model act with the runtime tools (read_file, write_file, web_fetch, web_search, shell) and any configured MCP tools. Actions are checked against active restrictions. Agents default to medium reasoning and never use repairs, so a failed check never repeats their actions.

Modifiers#

All three commands take named modifiers in parentheses before the prompt. Values are expressions, evaluated once and validated before the call. Unknown or duplicate names are syntax errors.

Modifier Values Effect
len word sentence paragraph long Length hint (guidance only)
fmt see Output formats Parse and check the answer
schema JSON Schema draft-07 Validate the answer; implies JSON
repairs 0–5 Extra attempts after a format or schema error
reasoning low medium high Reasoning effort, if the model supports it
hide True False (default) Suppress reasoning display when True; responses remain visible
model model id Per-call model
tokens Positive safe integer Maximum generated tokens per model turn, including reasoning
seed Integer 0..2147483647 ask only: request repeatable sampling where supported
temperature Finite number 0..2 ask only: control sampling variability
top_p Finite number 0..1 ask only: control nucleus sampling

The former show modifier is no longer accepted. Omit show=True (reasoning is now visible by default), and replace show=False with hide=True.

tokens is a hard generation budget, not a length hint or a separate thinking budget. The same limit applies independently to every repair attempt and agent tool-continuation turn. Omitting it preserves existing provider defaults. It maps to OpenAI max_output_tokens (or max_completion_tokens for seeded calls), Anthropic max_tokens, and Google maxOutputTokens. Invalid values fail before the model call; provider/model limits still apply. Legacy Anthropic manual thinking requires tokens to exceed its reasoning budget (low: 1024, medium: 4096, high: 16384); conflicting settings fail rather than silently enlarging the generation budget. If the model hits its token limit, the call fails with llm_error, not a successful partial answer, and format/schema repairs do not retry the truncated turn. Explicit budgets are recorded in effective.tokens and participate in recording/trace request matching, so changing a budget cannot silently reuse an old answer.

Model precedence: CLI --model, then the per-call model, then frontmatter model, then the provider default. OpenAI, Anthropic and Google are supported through their official clients; use bare model IDs or provider/model. See Models and authentication.

Randomness controls#

Set sampling modifiers directly in ask(...):

Parameters are optional named expressions, evaluated once in source order alongside other modifiers and before the prompt. The same values are reused for every repair attempt. Omitted sampling controls use provider/model defaults; no seed, temperature or top_p is invented. Sampling controls apply only to that ask expression, not to surrounding code or Markdown blockquotes. think and agent do not accept them; their existing modifiers and reasoning defaults are unchanged.

ask has no implicit reasoning effort. An explicit reasoning='low', 'medium' or 'high' always takes precedence. Models that cannot disable thinking use the SDK's lowest supported thinking setting with a compatibility warning.

Parameter Accepted values Meaning
seed Integer 0..2147483647 Request repeatable sampling where the provider supports it
temperature Finite number 0..2 Lower values reduce variability; 0 requests greedy sampling where supported
top_p Finite number 0..1 Nucleus sampling; smaller values narrow token choices (1 does not narrow them)

Unknown/duplicate names, or sampling modifiers on think or agent, are syntax errors. Out-of-range values, booleans, strings and None are runtime errors before the model call. The former randomness(...) prefix and eval(...) statement are no longer supported. Move sampling values into ask(...) and use assert and schemas for explicit output checks.

Provider limitations are diagnosed with warnings; the runtime keeps supported controls without changing the model, and preserves explicitly requested reasoning:

  • OpenAI: seeded calls use Chat Completions, which accepts seed; unseeded calls retain the Responses API. Chat Completions does not expose reasoning summaries, so requested summaries warn and are omitted; reasoning effort and runtime/MCP tool continuations are retained. Tool definitions and parallel-tool settings are omitted when no tools are enabled. Seeds are best-effort and deprecated by the upstream API, not a guarantee of identical output. Models must support Chat Completions; provider errors surface without retrying on a different API. Compatible GPT-5.1+ and GPT-6 models accept sampling with reasoning effort none. Models that require reasoning, or calls with explicit reasoning, may remove sampling controls. The provider adapter diagnoses model-specific restrictions.
  • Google: the Generate Content API receives seed, temperature and topP. A fixed seed with low temperature and a small nucleus is best-effort repeatability, not a guarantee. Gemini 2.5 Flash supports disabling thinking with a zero budget; Gemini 2.5 Pro and Gemini 3 models retain their lowest supported thinking setting with a warning.
  • Anthropic: seeds are unsupported. Temperature is capped at 1 with a warning. On compatible non-thinking models, set either temperature or top_p; if both are supplied, temperature wins and the adapter warns that top_p is ignored. Thinking and newer models may reject sampling altogether; unsupported controls are removed with warnings.

The response's effective.randomness records controls actually retained by the provider adapter. For sampling controls, null means the control was omitted/unsupported and provider defaults apply, not that a particular default numeric value was sent. effective.reasoningEffort is none when disabling thinking is honored, or null when the adapter cannot honor that setting; null does not mean thinking is disabled. Traces and pinned workflows include requested sampling controls in request identity; changing them cannot silently reuse an old response. Recreate pins and choose new trace files after editing source documents; legacy trace and generation-recording formats are not accepted by the append-only trace journal.

Even extreme settings cannot guarantee identical outputs from hosted models. Use --trace or --pin for deterministic offline replay. See the official OpenAI, Google and Anthropic adapter documentation.

Output formats#

fmt Accepts
text (default) Trimmed text, no parsing
integer JSON number without a fraction
float Any finite JSON number
boolean JSON true or false
array JSON array (a list)
object JSON object (a dict, not an array)
json Any JSON value

Parsing is strict: prose around JSON and Markdown code fences are rejected, and values are never coerced. A malformed or wrong-typed answer raises invalid_format.

Schemas and repairs#

schema accepts SPL type descriptors or raw JSON Schema. Both reject invalid output without coercion, defaults or removal of extra fields. A mismatch raises validation_failed with field paths.

Use enums, structs and aliases to describe typed output directly:

Struct fields are exact and required, including nullable fields. Metadata in brackets is model advice only, not a data constraint. Raw JSON Schema still uses strict Ajv validation when constraints such as minimum or minLength must be enforced:

Raw schemas validate dynamic JSON values; they do not install SPL type contracts or hydrate classes. Descriptor targets decode typed representations, including exact signed-64-bit integer tokens and distinct finite floats. Legacy fmt='integer' and fmt='float' alone still return dynamic numbers; use schema=int or schema=float when a typed numeric result is required.

repairs=n allows up to n more attempts, each with the previous answer and the validation errors. Only invalid_format and validation_failed are repaired; transport and tool errors are not. The prompt is not re-evaluated. Put business rules in assert, after the call.

Struct targets decode validated structural data; schema=Person hydrates a nominal instance only for a hydratable class Person. schema=struct(Person) instead returns structural field data, never a Person instance. A binding annotation checks the result and does not secretly configure the ask target. Typed JSON decoding preserves signed-64-bit tokens exactly; typed decoding or complete hydration failures use the same repair budget (zero by default, at most five extra attempts). Unsupported non-JSON schemas and ambiguous distinct targets fail before provider calls. See class schemas and migration.

Guidance: enforce and forbid#

enforce text: and forbid text: introduce indented blocks and add instructions to every model call inside, including calls in functions they invoke. Nested guidance combines. Guidance shapes prompts; it does not check the answer.
