The language

Language basics

The deterministic half of SPL: a Python-flavoured language with braces. Nothing on this page calls a model — given the same inputs it always produces the same results.

📌
Design decisions at a glance
  • Blocks use braces; the opening { must be on the same line as its keyword. Statements end at a newline (or ;).
  • Every modification of a variable starts with let: let x = 1, let x += 1, let d['k'] = 2. A bare x = … is a syntax error.
  • Scoping: bare { … } blocks and functions open a scope where let shadows outer variables; if, loops, try, enforce, forbid and restrict blocks do not, so results flow out of them. See Scope.
  • return exits immediately from any scope — the function, or the whole script at the top level.
  • Every string interpolates {expr}.
  • Strict parsing: unknown modifiers or values, break outside loops, a modification without let, and try without except are syntax errors (exit code 2).

Program structure

A script is an optional @{…} directive header followed by statements. # starts a comment that runs to the end of the line.


@{model='gpt-5'}        # header: only allowed before the first statement

let greeting = 'hello'  # a statement
log(greeting)           # an expression statement

Directives

The only directive in the MVP is model. Its value must be a plain string (no interpolation). The --model CLI option takes precedence over the directive.

Variables

let declares a variable and is how you change it: every modification starts with let, including compound operators (+= -= *= /= //= %=) and member or item targets. A bare x = 5 is a syntax error. Reading an unknown name is a runtime error.


let count = 0
let count += 1             # same as: let count = count + 1
total = 5                  # syntax error: variables are modified with 'let'

let user = {'name': 'Ada'}
let user.name = 'Grace'    # member assignment
let user['age'] = 36       # item assignment

Scope

let name = … binds in the current scope. Two constructs open a new scope: a bare { … } block and a function body (with its parameters). A let there shadows an outer variable of the same name and leaves it untouched; the shadow disappears at the closing brace.


let color = 'Blue'
{
    let color = 'Red'
    log(color)             # Red
}
log(color)                 # Blue

if/elif/else, for, while, try/except, enforce, forbid and restrict blocks do not open a scope: a let inside them updates the enclosing variable. That is what lets the answer of an LLM call leave a constraint block:


let color = None
enforce 'Your favorite color is blue' {
    let color = ?{len='word'} 'What is your favorite color?'
}
log(color)                 # the answer

try {
    let response = ?{fmt='object'} 'A joke about programmers'
} except err {
    let response = {'setup': 'none', 'punchline': err.reason}
}
log(response)              # visible here, whichever branch ran

Functions are closures that can read outer variables, but a let inside a function always binds locally. To share mutable state with a caller, mutate a list or dict (let cell[0] += 1).

Persistence

Top-level variables can be saved between runs with the variable store (--store). See CLI & runtime.

Compare it with a quoted name: type(x) == 'list'. There is no separate int/float distinction — both report 'number'.

Truthiness

None, False, 0, empty strings, empty lists and empty dicts are falsy. Everything else (including functions) is truthy.

Strings & interpolation

All four quote styles interpolate {expression}. Any expression is allowed, including calls and indexing. Substitution is as is: strings raw, True/False/None in Python spelling, lists and dicts as JSON.


let items = ['a', 'b']
let n = 2
log("found {n} items: {items}")          # found 2 items: ["a","b"]
log("first is {items[0].upper()}")       # first is A
log("{{literal}} and \{also literal\}")  # {literal} and {also literal}
log(r'{"raw": "no {interpolation} here"}')

Quote styles & escapes

FormBehaviour
'…'  "…"Single line; escapes and interpolation.
'''…'''  """…"""May span lines; escapes and interpolation. Ideal for prompts.
r'…'Raw: no escapes, no interpolation.

Valid escapes: \n \t \r \0 \\ \' \" \{ \}. Anything else is a syntax error, and so is a stray single } in a string — write }} or \}.

let label = 'many' if len(xs) > 3 else 'few'

Control flow

if / elif / else


if score >= 90 {
    let grade = 'A'
} elif score >= 80 {
    let grade = 'B'
} else {
    let grade = 'C'
}

for & while

for iterates lists, strings (characters) and dicts (keys). Several names unpack list items, which pairs well with items() and enumerate(). break, continue and pass work as in Python.


for i in range(3) { log(i) }

for code, language in items({'de': 'German', 'pl': 'Polish'}) {
    log("{code} = {language}")
}

let tries = 0
while tries < 3 {
    let tries += 1
    if tries == 2 { continue }
}

Functions

Define with def. Functions take positional arguments only (the count is checked), return None unless return is used, can recurse (up to a maximum call depth of 200) and close over their defining scope. return leaves the innermost function immediately, from inside any nested block, loop, try or constraint block; at the top level of a script it ends the script like success, optionally with a value.


def fib(n) {
    if n < 2 { return n }
    return fib(n - 1) + fib(n - 2)
}

def is_valid(msg) {
    let first = msg.splitlines()[0]
    return len(first) <= 72 and ': ' in first
}

Functions are the right place for validators — the deterministic code that decides whether to trust an LLM answer. See commit-message.

Built-ins

A compact standard library is available without imports: len, range, sorted, json_parse, log, and Python-style methods on strings, lists and dicts. The full list is on the Built-ins page.
