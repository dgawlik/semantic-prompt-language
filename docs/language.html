Language

SPL is a small Python-like language with colon-and-indentation blocks. This page covers the code inside spl fences: values, bindings, control flow, functions, built-ins and exact tools. Markdown blockquotes use a single optional @CTL(restrict=..., enforce=..., forbid=..., model=..., reasoning=...) header for agent controls. These controls are separate from SPL syntax; human input in blockquotes is requested in plain language, without a special marker.

Values and strings#

Values include None, True/False, numbers, strings, lists, dictionaries with string keys, functions, immutable type descriptors and nominal class instances. Simple statements end at a newline or ;. # starts a comment, and a trailing \ continues a line.

Escapes: \n \t \r \0 \\ \' \" \{ \}. Python-style operators work as expected: + - * / // % **, comparisons, in/not in, and/or/not, a if cond else b, indexing, slicing with negative indexes, and d.key as a shorthand for d['key'].

Lists and strings support value[start:stop:step]. The stop is exclusive; omitted bounds select the sequence ends in the direction of the step, which defaults to 1. Negative indexes count from the end, and out-of-range bounds are clipped. Bounds and steps must be integers or None (None uses the omitted default); a zero step is a runtime error. List slices are new shallow copies; string slices use Unicode code points. Slices are read-only expressions, not assignment targets.

Bindings and scopes#

let declares a name in the current block; plain assignment updates the nearest existing declaration. Every block is a child scope, so inner let shadows outer names and does not leak out. Each loop iteration gets fresh variables.

Declare a result before a block when the block should set it: let answer = None and then answer = ... inside.

Control flow and expressions#

if/elif/else, for, while, break, continue and pass use Python-like layout, but keep SPL's lexical scopes. for k, v in items(d) unpacks pairs. Blocks and if are expressions that yield their last expression, or None. Anonymous value-producing blocks begin with a bare :, as in result above. object() is an empty dictionary; a block containing only pass yields None.

Functions#

def defines a function with lexical closures and recursion. Functions return None unless they use an explicit return. Functions are first class citizens and can be passed around. lambda defines lambda function defined inline.

Modules#

Import reusable raw .spl files from a Markdown workflow's fenced SPL blocks, or from another .spl module, using JavaScript-style named or namespace imports:

The corresponding helpers.spl contains plain SPL, without Markdown frontmatter or fences:

Every top-level declaration is exported automatically: variables, functions, enums, type aliases, structs, classes, and imported bindings. Block-local declarations are not exported. No export keyword is required. Named imports can also bring type declarations into scope for annotations.

Imports are top-level statements. Local paths must start with ./ or ../ and explicitly end in .spl; they resolve relative to the importing file, not --cwd. Bundled standard library modules use a bare name, such as 'markdown', from any SPL file or workflow code fence, without installation or a local helper file. Other package names, remote URLs, Markdown modules, default imports and bare side-effect imports are not supported.

The complete dependency graph is linked and type-checked before execution. Dependencies initialize before the importing file's statements, once per workflow run or notebook session. Module variables are isolated from the caller; functions retain their module's lexical scope. Imported bindings are live and cannot be reassigned, and namespace properties are read-only. Exported lists and objects remain mutable. Circular imports, missing files/exports, and invalid module source report explicit errors.

Modules use the caller's model, arguments, environment and tool working directory. Module model directives are not supported, and return/success cannot terminate module initialization. Imported functions run under the caller's active restrictions. Resetting a notebook session clears its module cache. Traces and pinned workflows capture module source so replay does not need the original .spl files.

Markdown standard library#

The bundled markdown module is written in SPL. Build a document dynamically, then call to_string() to get a normal string suitable for success, prompts, or write_file:

Named imports also work: import { Document, bold } from 'markdown'. Each Document() owns its own block list. Builder methods return the same document, so calls can be chained. All arguments shown below are required; SPL functions do not have default arguments.

Method Output
heading(text, level) Heading with level 1 through 6
paragraph(text) Paragraph containing inline Markdown
bullet_list(items) Bullet list of strings; multiline items are indented
ordered_list(items, start) Numbered list; start and subsequent markers must have at most nine digits
quote(text) Blockquote, including multiline text
code_block(text, language) Fenced code block; use '' for no language
table(headers, rows) GFM table; string cells, nonempty headers, matching row widths
thematic_break() Horizontal rule
raw(text) Unmodified Markdown block, apart from line-ending normalization
to_string() Blocks joined with blank lines and a final newline; '' for an empty document

to_string() is repeatable and does not consume the document. Empty raw blocks and empty lists add nothing. Raw text and paragraphs preserve whitespace, including any supplied trailing newlines. Line endings are normalized to \n. Tables escape pipe delimiters and replace cell newlines with <br>. Code fences grow to accommodate embedded backticks and preserve code whitespace.

Inline helpers return strings: bold(text), italic(text), code(text), link(label, url), image(alt, url), and escape(text). Paragraphs, headings, lists, quotes, table cells, and formatting helpers accept Markdown, so use escape(text) for literal dynamic text. Link labels and image alt text are escaped automatically; whitespace, backslashes and angle brackets in destinations are percent-encoded. Inline code handles embedded backticks and padding, normalizes newlines to spaces, and requires nonempty text. Headings, link labels, image alt text, bold/italic text, and code language labels must be single-line; code language labels must not contain backticks. These helpers generate Markdown, not sanitized HTML or validated URL schemes.

Gradual typing#

Annotations are optional enforced contracts, not advisory lint hints. Untyped bindings remain dynamic. Known typed violations block execution before model calls; unknown values are validated at typed boundaries without coercion, defaults or field removal.

Built-in types and existing type declarations remain available after if, loops, and try/except blocks. An untyped alias used as an annotation must still identify the same type on every possible control-flow path.

Types at a glance#

Type Accepted values
int Signed 64-bit integers; checked arithmetic, no overflow wrapping
float Finite binary64 numbers, distinct from int
str Strings
char Strings containing exactly one Unicode scalar value
bool True or False, not integers
None The null value, not an absent field
object Dynamic string-keyed dictionaries, not nominal class instances
list[T] Lists whose elements satisfy T
A | B Values satisfying either member; narrow before member-specific operations
fn(T1, T2) -> R Callables with the declared parameter and return contracts

Typed literals select the representation: let count: int = 2, but let ratio: float = 2.0. Neither let count: int = 2.0 nor let ratio: float = 2 is valid. Untyped numbers keep their existing representation; use int(value) or float(value) explicitly to enter typed numeric code. int(...) rejects fractions, booleans and out-of-range values; conversion to float can lose integer precision. Mixed int/float arithmetic requires explicit conversion. Integer / produces a float. Counts from len and range remain untyped numbers.

Transparent type aliases#

Declare read-only, transparent aliases with optional semantic advice:

Aliases accept the same values and operations as their underlying types, without implicit conversion. Advice is included in generated schemas' descriptions, including when an alias is used as a field or list element; it does not enforce extra constraints. Aliasing an alias inherits its advice, with newly supplied keys overriding inherited keys. Field advice is appended separately. type(value) remains the type-name builtin.

Enums, structs and functions#

Enums accept matching strings directly and are subtypes of str. Structs are structural: equivalent field contracts are interchangeable. Fields are exact and required; nullable does not mean absent, so note above must be present even when it is None. Metadata such as str [min=2, desc='Name'] is model advice, not a validity constraint. Use assert for business rules, or explicit JSON Schema for strict data constraints. Function parameters, results and callable fields are checked at their typed boundaries. A union value can be assigned or passed to another union, including a list element contract, when every source alternative is accepted by the destination. Member order does not matter; an alternative missing from the destination must be narrowed first.

Validation, narrowing and mutation#

validate(value, Type) checks values and returns a typed view, or fails. For a class target it explicitly converts structural field data into a nominal instance. isinstance(value, Type) tests without converting and narrows within a branch:

Neither operation converts untyped numbers. isinstance never converts structural data into a class. validate(data, Class) checks all declared fields and creates a complete instance without running the constructor, including for ordinary classes. Missing or extra fields fail; no defaults or numeric conversions are inserted. Class conversion also applies to nested fields, lists and union members; distinct ambiguous conversions fail. Converted field dictionaries and containers are copied rather than rewriting the source.

Successful tests and validation install persistent contracts on mutable values. These survive untyped aliases, index/member writes and bulk mutators. For example, an untyped alias cannot append an integer to a list[str]. Mutable contracts are invariant: list[Color] cannot be used as list[str]. Failed bulk mutations leave the whole value unchanged. Narrowing expires after relevant assignment or potentially mutating calls.

Classes and structural projections#

Classes have nominal identity, declared fields, and implicitly bound self in methods. Normal construction calls the constructor named after the class and must initialize every field. Use hydratable class only when constructor-free JSON hydration is safe:

struct(Person) describes structural field data, not a Person instance. To explicitly turn that data into an instance, use validate(data, Person):

This conversion bypasses constructor normalization and side effects. Direct schema=GeneratedPerson still requires a hydratable class declaration.

object(person) makes a deep snapshot and drops named function properties. Validate that snapshot against struct(Person) when a checked field view is needed; validation rejects missing required fields, including callable fields dropped by projection. Use explicit projection before serializing class instances. See Schemas and repairs for typed model output, typed-data.md for an offline workflow, and Typing migration for the full migration rules.

Runtime inputs: $env and $args#

$env.NAME or $env['NAME'] reads a process environment variable as a string. $args[0], $args[1], … read the CLI's repeated --arg values. Missing variables and out-of-range indexes return None. Both are read-only snapshots and are never persisted by stores.

Logging#

log(value, ...) writes to stderr at info level. log(level=debug)(value) selects error, info or debug. Debug output appears only with --log-level debug; --silent hides all logs. Objects and lists are logged as indented JSON, including when mixed with text arguments. Every continuation line carries the same log tag. Terminal output colors JSON tokens; redirected logs are plain text by default. See console formatting.

List callbacks and lambdas#

lambda x: expression creates an anonymous function that implicitly returns its expression. Use lambda: expression for no parameters, or comma-separated names for multiple parameters. Lambdas capture lexical bindings like def, can be stored or returned, and accept a checked fn(...) -> ... contract. Parameter annotations and default arguments are not supported in lambda syntax. Parenthesize a lambda to call it immediately: (lambda x: x + 1)(2).

These methods are available only on lists, not strings or dictionaries:

Method Behavior
xs.map(callback) Return a new list containing callback(item) for each item
xs.filter(callback) Return a new list of original items whose callback result is truthy
xs.reduce(callback[, initial]) Fold left with callback(accumulator, item) and return the final accumulator

Callbacks can be lambdas, named functions, or built-ins. Map and filter pass only the item, not an index. Reduce uses the initial value when supplied; otherwise it starts with the first item. An empty list reduces to its initial value, including None; without one it raises a runtime error. A singleton without an initial value returns its item without calling the callback.

Callbacks run sequentially, including asynchronous operations, and failures propagate normally. Each operation takes a shallow snapshot of the list before invoking callbacks; it does not mutate the source itself. Changes a callback makes to the source do not add or remove work from that snapshot. Filter preserves the original item references.

Exact tools#

Tools are ordinary functions that never call a model. Paths are relative to --cwd, and every call is checked against active restrictions.

Function Result
read_file(path) File contents as UTF-8 text
write_file(path, content) Writes the file and returns a confirmation
web_fetch(url) Response body as text (30 s timeout, up to 5 redirects)
web_search(query) Search results as text
shell(command) Combined stdout/stderr; a nonzero exit raises tool_error (120 s timeout)

shell runs through the platform shell (cmd.exe on Windows, /bin/sh elsewhere). External state can still change between runs; "exact" means no model is involved.
