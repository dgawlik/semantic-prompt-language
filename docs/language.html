Language basics

The deterministic core of SPL: Python-flavoured expressions, braces, lexical block scopes, and explicit assignment. Model calls are distinct expressions, not implicit behavior of ordinary functions.

Read a script by its boundaries: let names values, ask and think mark model judgment, agent opts into model-selected actions, and assert exposes acceptance rules. Keep routine computation in ordinary code so the variable parts and their guards remain easy to spot.

Design decisions at a glance

  • Blocks use braces; the opening { must be on the same line as its keyword. Statements end at a newline (or ;).

  • let declares/redeclares a local; x = … and x += … update an existing local. Collection assignment uses d['k'] = 2, without let.

  • Block scoping: each block has a child scope. Reads and assignments search outward; let shadows enclosing names. See Scope.

  • return exits immediately from any scope — the function, or the whole script at the top level.

  • Every string interpolates {expr}.

  • Unknown/duplicate modifier names, break outside loops, and try without except are syntax errors. Modifier values are expressions validated at runtime.

  • Model commands use ask(options) 'prompt', think(options) 'prompt', and agent(options) 'prompt'. Named options support multiple lines and trailing commas. With no options, omit the group or use (). Prompts remain outside the parentheses.

Human input#

human 'question' requests text from the caller, not a model. It evaluates a string question, durably saves a pending request, and suspends a checkpoint run. SPL prints JSON and exits with code 3; it never reads stdin or waits at a terminal.

Start with --checkpoint run.jsonl, then submit the matching request ID with --resume run.jsonl --answer-for <id> --answer "..." or --answer-file feedback.txt. The expression returns the exact answer, including empty text and whitespace. There are no LLM modifiers, schemas, automatic repairs, or scoped model guidance for human input. Use ordinary assertions or explicitly ask again to validate text.

Questions can occur inside functions, loops, nested expressions, and policy blocks. Suspension is not a failure and cannot be caught by except. Each dynamic question gets its own request ID, even when it comes from the same source line. Executable scripts containing human require checkpoint mode before any script effects; --check remains syntax-only. human is now reserved and cannot be used as a variable or function name. See Human in the loop.

Program structure#

A script is an optional @(…) directive header followed by statements. # starts a comment that runs to the end of the line.

Directives#

The header directive is @(model='...'), whose value must be a plain string without interpolation. Parentheses may span lines and have a trailing comma. Precedence is CLI --model, per-call model, header, then SDK default.

Variables#

let name = expression declares or redeclares a local. Assignment and compound operators (+= -= *= /= //= %=) update existing locals; they do not use let. Member/item targets also omit let. Unknown reads and assignment to an undeclared local are catchable runtime errors.

Runtime inputs: $env and $args#

These special variables are available in every scope, including functions and string interpolation. They are snapshots taken at the start of each run, not ordinary bindings.

  • $env is a read-only dict of process environment variables. $env.NAME and $env['NAME'] return a string, including '' for a set-but-empty variable. An absent name returns None. Bracket access also supports names containing punctuation. Environment names use the spelling exposed by the host process.
  • $args is a read-only list of strings supplied with repeated CLI --arg options, in command-line order. The script path and interpreter options are not included. Without --arg, it is empty. Out-of-range integer indexes return None; negative indexes count from the end, as with ordinary lists. Non-integer indexes fail.

The special names cannot be declared, rebound, or used as parameters or loop variables. Assignments to their members/items and mutating methods raise catchable runtime_error, even through aliases such as let args = $args. Use $args.copy(), list($args), $args[:], or $env.copy() to create a normal mutable copy. Copies have ordinary missing-index/key errors; this does not change ordinary dict/list behavior.

The runtime does not automatically add either value to a variable store. Explicitly assigning a value or alias to a top-level variable can persist it, so do not persist, log, or interpolate sensitive environment values into prompts unintentionally. Replay uses the current run's inputs, not recorded environment variables or arguments. Other $-prefixed variable names are syntax errors.

Scope#

let name = … binds in the current scope. Every block creates a lexical child scope. Inner declarations shadow enclosing names and cannot be accessed from a parent scope. Reads and assignments search outward through the full lexical chain for the first declaration. There is no hoisting: a local appears when execution binds it.

Conditionals, loops, exception handlers, and guidance/restriction blocks follow the same rule. Each loop iteration has fresh locals, including its loop variables. Caught failure names belong to their handler. To keep a result, declare it outside and assign inside:

enforce provides positive scoped prompt guidance and forbid provides negative guidance. Both create child variable scopes, but neither verifies model compliance.

Functions close over their lexical defining scope. They can read or assign enclosing declarations; let instead declares locally and shadows an enclosing name. Lists and dicts remain mutable across scopes.

Block and conditional expressions#

A block or selected if/elif/else branch yields its final expression. An empty branch, a block ending in a statement, or an unmatched conditional returns None. Only the selected branch runs. {} remains an empty dictionary; use { pass } for a block yielding None. Functions still require explicit return.

Persistence#

Top-level variables can be saved between runs with opt-in --store, even after a script failure. Persistence is not a transaction or an action log. It is allowed during workflow trace replay, but forbidden during legacy generation replay. See CLI & runtime.

Types & values#

type() Literals Notes
'None' None Falsy.
'bool' True False Python spelling.
'number' 42 3.14 1e-3 One numeric type. int() truncates, float() parses.
'str' 'a' "a" '''a''' r'a' Indexed by Unicode character.
'list' [1, 2, 3] Mutable, trailing comma allowed.
'dict' {'a': 1} Keys must be strings. Insertion ordered. Also readable as d.a.
'function' def f(x) { … } First-class values.

Model calls can request typed output with fmt='integer', 'float', 'array', 'object', 'text', or 'boolean'. Non-text formats validate strict JSON and return ordinary SPL values; fmt='json' accepts any JSON value. See output formats and examples.

type() returns a string

Compare it with a quoted name: type(x) == 'list'. There is no separate int/float distinction — both report 'number'.

Truthiness#

None, False, 0, empty strings, empty lists and empty dicts are falsy. Everything else (including functions) is truthy.

Strings & interpolation#

All four quote styles interpolate {expression}. Any expression is allowed, including calls and indexing. Substitution is as is: strings raw, True/False/None in Python spelling, lists and dicts as JSON.

Quote styles & escapes#

Form Behaviour
'…' "…" Single line; escapes and interpolation.
'''…''' """…""" May span lines; escapes and interpolation. Ideal for prompts.
r'…' Raw: no escapes, no interpolation.

Valid escapes: \n \t \r \0 \\ \' \" \{ \}. Anything else is a syntax error, and so is a stray single } in a string — write }} or \}.

Operators#

Lowest to highest precedence:

Operators Description
x if cond else y Conditional expression.
or Logical or (short-circuit).
and Logical and (short-circuit).
not Logical negation.
== != < <= > >= in not in Comparison and membership. == is deep for lists and dicts. Ordering works on numbers, strings and lists.
+ - Add / subtract. + also joins two strings or two lists — mixing types is an error (use interpolation or str()).
* / // % Multiply, divide, floor-divide, modulo. * repeats strings and lists. Division by zero is a failure.
-x +x Unary sign.
** Power.
f(x) a[i] a[i:j] a.b Call, index, slice, member. Negative indexes count from the end.

Control flow#

if / elif / else#

for & while#

for iterates lists, strings (characters) and dicts (keys). Several names unpack list items, which pairs well with items() and enumerate(). break, continue and pass work as in Python.

Functions#

Define with def. Functions take positional arguments only (the count is checked), return None unless return is used, can recurse (up to a maximum call depth of 200) and close over their defining scope. return leaves the innermost function immediately, from inside any nested block, loop, try or constraint block; at the top level of a script it ends the script like success, optionally with a value.

Functions are the right place for validators — the deterministic code that decides whether to trust an LLM answer. See commit-message.

Built-ins#

A compact standard library is available without imports: len, range, sorted, json_parse, log, and Python-style methods on strings, lists and dicts. The full list is on the Built-ins page.
