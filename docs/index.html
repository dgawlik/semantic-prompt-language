Opt-in Types#

Language is dynamic but has full support for opt-in static type checker. There are supported primitive types, structs, classes and dynamic catch-all objects. Functions are first class citizens.

Why SPL?#

  1. Short loops. One file, run directly. --check validates syntax without a model, and --trace run.jsonl resumes recorded work automatically and replays completed runs deterministically.
  2. Exact code where it matters. Control flow, arithmetic and I/O never call a model. ask and think generate values without tools; agent expressions and blockquotes can act.
  3. Guards you can see. fmt, schema and assert check data; restrict checks actions. Prompt guidance (enforce, forbid, len) is kept separate from validation.
  4. Readable. Inputs, prompts, checks and outputs sit in one document, top to bottom.
  5. Optional typed contracts. Enums, structs, classes and reusable aliases describe model output. Annotations, typed functions and persistent mutable contracts enforce consistency; assertions still check whether the content makes sense.

How a run works#

  1. Frontmatter opts the file in. All fences are parsed first, so syntax errors fail before anything runs.
  2. Fences and blockquotes execute in document order in one shared scope.
  3. A blockquote sends its text, visible bindings and runtime tools to an agent. The model calls tools to invoke functions, read environment values, request human input and load/save shared variables. It never submits generated SPL.
  4. ask, think and agent use the official OpenAI, Anthropic and Google clients, one fresh conversation per call.
  5. success prints the result on stdout. Logs go to stderr.

Non-goals#

  • Full Python, inheritance, recursive schemas or general-purpose automatic source conversion.
  • Reproducible model output, transactional actions or an OS sandbox.
