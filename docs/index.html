  • js fences are native JavaScript on Node.js. The spl-lang library is already imported, so ask, struct, writeFile and markdown need no import.
  • struct and enumOf describe the data a model must return. Annotations such as desc are written for the model to read.
  • ask(prompt, { schema: Card, repairs: 1 }) validates each answer against Card, allows one repair attempt and returns a plain JavaScript object.
  • The blockquote is an agent command. The model loads cards and saves hardest with tools; the next fence uses hardest as an ordinary variable.
  • writeFile is an exact tool: it never calls a model and obeys restrictions.

Generate reusable functions#

@CODEGEN asks the model for JavaScript functions and defines them in the shared scope. Later fences and blockquotes call them like any other function. In code, await codegen(description) does the same and returns the function.

With --trace, the generated code is also saved beside the workflow, here as codegen.sieve.js. Its first line hashes the description, and later traced runs reuse a matching file without calling the model:

See Code generation for validation and cache rules.

Types the model can read#

Types are ordinary JavaScript values built with library functions. They validate data, turn JSON into JavaScript objects and render the JSON Schema that is sent to the model, including any annotations you attach.

union(float, int) accepts either number. .methods({...}) makes parsed answers instances with methods, so person.toString() works on the model's output. See Types.

Why SPL?#

  1. Short loops. One file, run directly. --check validates the document without a model, and --trace run.jsonl resumes recorded work and replays completed runs.
  2. Plain JavaScript where it matters. Control flow, arithmetic and I/O are native code on Node.js, with the standard library and your own modules one import away.
  3. Guards you can see. fmt, schema and assert check data; restrict limits what tools and agents may touch. Prompt guidance (enforce, forbid, len) is kept separate from validation.
  4. Readable. Inputs, prompts, checks and outputs sit in one document, top to bottom.
  5. Typed model output. Enums, structs, classes and named aliases describe what a model must return. Annotations advise the model; assertions check whether the content makes sense.

How a run works#

  1. Frontmatter opts the file in. Every fence is compiled first, so syntax errors fail before anything runs.
  2. Fences and blockquotes execute in document order in one shared scope.
  3. A fence runs as JavaScript with top-level await. ask, think and agent call the official OpenAI, Anthropic and Google clients, one fresh conversation per call.
  4. A blockquote sends its text, the visible bindings and the runtime tools to an agent. The model calls tools to load and save shared variables, invoke functions, read environment values and ask a person. The @CODEGEN form generates function declarations instead.
  5. success(value) ends the run and prints the value on stdout. Logs go to stderr. An uncaught failure prints a JSON payload and exits with code 1.

Non-goals#

  • A custom programming language. Workflow code is JavaScript; the earlier SPL syntax is gone.
  • A sandbox. restrict governs the library's tools, agents and MCP servers, not Node.js APIs that your own code calls.
  • Reproducible model output. Use traces and pins to replay a recorded run.
