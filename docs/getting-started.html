Getting started

Install the CLI, sign in to GitHub Copilot, then write and refine a workflow in a short edit-run loop.

  • Install

Install#

SPL needs Node.js 20+. From a checkout, run npm install in lang/ and use node dist/cli.js in place of spl.

spl login reuses existing credentials (Copilot CLI, gh, or COPILOT_GITHUB_TOKEN, GH_TOKEN, GITHUB_TOKEN). Otherwise it runs GitHub's device flow and saves a token in ~/.spl (override with SPL_HOME). spl logout deletes it. Workflows that never call a model, --check and replay need no login.

Write a workflow#

Document structure#

  • Frontmatter must declare extension: semantic-prompt-language and version: 1. Optional model sets the default model; optional preamble is added to every model request. Unknown fields are errors.
  • spl fences are complete SPL units; a block or statement cannot span two fences.
  • Blockquotes are natural-language steps; see Natural language & models.
  • Everything else (headings, prose, other code fences) is commentary.

Blocks run in document order in one shared scope. success, fail and a top-level return end the whole document.

The iteration loop#

Replay needs the same model requests in the same order. After changing a prompt, record a new trace. Explicit tool calls still run during replay; see traces and replay.

VS Code extension#

The extension in vscode/ adds parser-backed diagnostics, completions, hover, go to definition, document symbols, highlighting for spl fences and @name markers, and Markdown preview highlighting. Type splworkflow for a new document.

Run the tests#

Tests are offline. To include authenticated live tests in PowerShell, run $env:SPL_LIVE_TESTS='1'; npm test, then remove the variable.
