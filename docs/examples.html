Examples

Every example is a runnable .spl file in lang/examples. Run them from the lang folder, for example spl run examples/hi.spl: the relative paths they read and write resolve against the working directory. The first lines of each example show its command and arguments.

Getting started#

Blocks, references, typed outputs and human input, a few lines at a time.

Hello, SPL#

A .spl file is TypeScript. Markdown comments like this one are commentary, and each --- block is an instruction for a model. Everything runs top to bottom, and the library (ask, Struct, writeFile, markdown, ...) needs no import.

file defaults

Setting Value
model gpt-6-luna
enforce Be concise.

The agent reads cards through a tool and must save a value that fits Card.

agent block

Setting Value
reasoning high

Pick the item of @cards whose card a beginner would find hardest ->[Card] @hardest

Source: hi.spl

Decisions#

decision() answers a question about the evidence with a boolean, so code can branch on it. With cutoff, it is true when the probability of yes is above the cutoff; with labels, the model picks a label and the result is the boolean that label stands for. OpenAI and Google answer with their decision endpoints, whatever the model below; Anthropic models simulate one.

file defaults

Setting Value
model gpt-6-luna

Source: decision.spl

Typed data without a model#

Types are built with library functions. This workflow uses no model calls or credentials:

It covers primitives, named aliases, enums, exact structs, nullable fields, unions, annotations, classes with methods, validation, coercion and JSON Schema output. With a model, outputType: Person in an ask block coerces the answer into the same objects. Annotations are advice for the model; use assertions for business rules.

Source: typed-data.spl

Developer workflows#

Agents and exact tools around a repository: reviews, release notes, issue triage and generated code.

Review the riskiest source files#

An agent picks and reviews three files inside ./src, an ask block turns its notes into typed findings, and plain code decides whether the run fails.

file defaults

Setting Value
model gpt-6-luna

agent block

Setting Value
restrict {"fs":"./src","exec":"git"}
forbid suggesting purely stylistic changes

List source files with git ls-files src.
Then read the 3 files that are most likely to contain security problems or correctness bugs,
and review only those. List each finding with its location, why it matters and a suggested fix -> @notes

ask block

Setting Value
outputVar review
outputType Review

Convert these review notes into structured findings: @notes

agent block

Setting Value
restrict {"fs":"./reports"}
model gpt-6.1-sol

Convert @groups to a Markdown report and write it to './reports/review.md'

Source: code-review.spl

Release notes from git history#

Collects commits since the latest tag, writes user-facing notes and prepends them to CHANGELOG.md. Pass the new version as the first argument.

file defaults

Setting Value
model gpt-6-luna

ask block

Setting Value
outputVar draft
enforce Write for users of the product: describe the impact, not the implementation
forbid inventing changes that are not in the commits, and listing internal refactors or CI tweaks

Group @commits into the sections "Features", "Fixes" and "Other" (omit empty sections) and
write Markdown release notes for @version. Start with the heading ## <version>, use ### for sections
and one bullet per change.

Source: release-notes.spl

Triage unlabeled GitHub issues#

Classifies open issues without labels and applies the labels only after a human approves the plan. Needs an authenticated gh CLI. Pass --arg owner/repo to target another repository. Enums constrain labels and priorities, and a named list type receives the whole batch. Field annotations are advice, so code checks nonempty reasons.

file defaults

Setting Value
model gpt-6-luna

ask block

Setting Value
outputVar plan
outputType TriagePlan
forbid judging an issue by its title alone when the body says otherwise
repairs 1

Classify every issue in @issues with exactly one label from @LABELS, a priority and a one-sentence reason.
Crashes, data loss and security problems are high priority.

agent block

Show the @table lines and ask the human "Apply these labels? (yes/no)" ->[Str] @approved

Source: triage-issues.spl

Extract an invoice into accounting-ready JSON#

Turns a pasted or OCR'd invoice into structured data. Monetary amounts use integer cents. The output type checks the shape; exact arithmetic checks the numbers, because a model can produce valid JSON with wrong totals.

file defaults

Setting Value
model gpt-6-luna

ask block

Setting Value
outputVar invoice
outputType Invoice
forbid filling in values that are not printed on the invoice
repairs 1

Extract the invoice in @text. Dates are ISO YYYY-MM-DD, currency is an ISO 4217 code,
and there is one entry per line item. Convert printed monetary amounts to integer cents
(for example, 12.50 becomes 1250).

Source: extract-invoice.spl

Translate product docs without breaking them#

Translates a Markdown announcement into several languages, then verifies deterministically that links, e-mail addresses, code spans and the heading structure survived. Target languages come from the arguments.

file defaults

Setting Value
model gpt-6-luna

ask block

Setting Value
outputVar translations
outputType Dict
enforce Keep the Markdown structure, URLs, e-mail addresses and code spans exactly as in the source, Use the product's informal, friendly tone and localize UI paths such as menu names

Translate the Markdown in @source into every language code in @languages.
Return an object that maps each language code to its translated Markdown.

Source: translate-docs.spl

Incident report from application logs#

Parsing and counting are plain code, so the numbers in the report are exact. The model only writes the narrative, from the extracted facts rather than the raw log.

file defaults

Setting Value

forbid speculating beyond what the errors and counts show; mark guesses as hypotheses

Write a blameless incident report in Markdown for errors between @first and @last.
Use the sections "Summary", "Timeline", "Impact", "Likely root cause" and "Follow-ups",

The web, MCP servers, state between runs and a person in the loop.

Research digest with checked citations#

Searches the web for a topic, reads the top results, and writes a short digest. Page fetches are restricted to the hosts of the chosen results, and every citation must point to a page that was actually fetched.

file defaults

Setting Value
model gpt-6-luna

ask block

Setting Value
outputVar urls
outputType List(Str)

From these search results pick up to 3 URLs of primary sources (official docs, specs, project blogs)
over aggregators: @results

ask block

Setting Value
outputVar digest
forbid facts that are not supported by the pages

Write a Markdown digest about @topic from @pages: a 3-sentence overview, then up to 5 bullet points
with key facts. End each bullet with its source URL in square brackets.

Source: web-digest.spl

Answer questions from an MCP docs server#

Needs an MCP configuration with a server named docs that exposes a search tool. MCP tools are available only to agents; restrict: { mcp } limits which ones a block may call.

file defaults

Setting Value
model gpt-6-luna

agent block

Setting Value
restrict {"mcp":"docs/search"}

Use docs/search to answer @question
End with a line "Sources:" followed by the URLs of the pages you used ->[Str] @answer

ask block

Setting Value
outputVar summary
forbid adding facts that are not in the answer

Rewrite this answer as at most five short bullet points followed by its sources: @answer

Source: mcp.spl
