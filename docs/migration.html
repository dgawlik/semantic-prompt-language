Migrating from 1.x

SPL 2.0 removes the custom SPL language. Workflow code is now native JavaScript in js fences, and everything the language had as syntax is a function of the spl-lang library. This guide maps every 1.x construct to its replacement and lists the behavior that changed.

Migration is manual: there is no compatibility mode and no converter. A spl fence is a syntax error that points here. Blockquotes, frontmatter, CLI options, traces, pins, MCP configuration and logging work as before; recorded traces and locked workflows must be recreated because their source changed.

Blockquotes#

Blockquotes are unchanged: the same agent tools, @name markers, @validate[Type], @CTL(...) and @CODEGEN. Three details differ:

  • call_function calls JavaScript functions and passes JSON values as they are; arguments are no longer decoded against parameter annotations.
  • @CODEGEN generates JavaScript function declarations, and codegen(description) does the same from code.
  • Script arguments are @args; the agent's load_variable still accepts the old $args name.

Behavior differences#

  • Everything asynchronous needs await. 1.x ran model calls and tools implicitly in sequence. In JavaScript they return promises. A map over a model call yields promises: use await Promise.all(items.map(item => ask(...))), which runs the calls concurrently, or a for loop to run them one by one.
  • No typed 64-bit integers. Numbers are JavaScript numbers. int accepts safe integers (up to 2^53 - 1) and float any finite number, including integers. There is no separate integer representation, no checked overflow and no exact decoding of larger integer tokens.
  • No static type checker and no persistent contracts. Annotations on variables and parameters do not exist at run time, --check does not check types, and a value that passed parse can be changed freely afterwards. Types check data where you apply them: schema, @validate, parse, is and validate. TypeScript in ts fences is erased, not checked, when the workflow runs; the VS Code extension reports type errors while editing. The type_error status code is no longer produced.
  • Annotations are advice. As before, field and alias annotations describe data to the model and never reject a value.
  • const is not enforced across fences. Top-level names live in one shared scope with REPL rules: redeclaring a name in a later fence rebinds it, and a top-level const can be reassigned. Inside functions and blocks, JavaScript's usual let/const scoping applies.
  • Imports resolve against the working directory. 1.x resolved .spl imports next to the importing file. JavaScript imports resolve against --cwd, are loaded and cached by Node.js and need explicit export. Imported names are live, read-only bindings as before. spl-lang and spl-lang/markdown always resolve to the running copy of the package, so helper modules need no local install.
  • Helper modules are not recorded. 1.x captured module source in traces and locked workflows. Now helpers are imported from disk again on replay: a locked workflow that imports local helpers is not self-contained, an edited helper changes the result and a deleted one fails.
  • --check is a syntax check. It compiles fences, parses controls and verifies static relative import declarations. It no longer type-checks, and dynamic import() calls are not verified.
  • Native Node.js APIs are outside the runtime. In 1.x all I/O went through tools. Now code can call node:fs, fetch or child_process directly; such calls are not checked by restrict, not recorded by --trace or --pin, and run again on replay.
  • Replay runs your JavaScript again. Recorded library effects return their recorded results, but Date.now(), Math.random() and direct file reads produce new values. A changed value that reaches a prompt or tool argument makes the replay fail with a mismatch.
  • Fences run on the main thread. They are ordinary JavaScript: a long synchronous loop blocks log rendering, timers and Ctrl+C handling until it yields. Add await points or move heavy work to a worker thread or child process.
  • Truthiness and equality are JavaScript's. Empty arrays and objects are truthy, == on arrays and objects compares identity, and a missing argument is undefined, not None. Use ?? for defaults: args[0] ?? 'world'.
  • Strings interpolate only in template literals. 'Hello {name}' is now a literal string. Search migrated prompts for braces inside ordinary quotes.
  • Failures are exceptions. catch receives a Failure object rather than a dictionary; line and command are filled in only when the failure ends the document. success is implemented by throwing, so a catch-all must rethrow what it does not handle. Any other uncaught JavaScript exception ends the document as runtime_error.
  • Classes need no opt-in. hydratable is gone. A class type hydrates plain data into instances without running the constructor, unless the class has a static fromJSON(data).

Embedding API#

SPL 1.x SPL 2.0
parse(source) for SPL source parse(code, { language }) for JavaScript or TypeScript
checkProgram, loadModules checkWorkflow(workflow, cwd); imports are native
encodeJson, decodeTypedJson, schemaForType, validateType, validateValue, testValue, project JSON.stringify, Type.parseJson, Type.schema, Type.parse, Type.is, Type.data
run(program, { source }) naming codegen caches run(workflow, { file }); source still labels failure payloads
Language only available inside workflows import { ask, struct, ... } from 'spl-lang' in any Node.js program

parseMarkdown, run, ExecutionSession, Logger, AiBackend, Trace, Pin and the backend interfaces keep their shapes. See Embedding.

Editor#

The VS Code extension no longer ships an SPL grammar, .spl language, snippets for SPL statements or a Markdown preview highlighter. Fences get JavaScript and TypeScript language features from the TypeScript language service, and notebook code cells are JavaScript or TypeScript cells. See the extension guide.

The .spl file extension now names the block format for JavaScript workflows, which the extension colors and completes. It is not the 1.x language: a 1.x script in a .spl file is rejected with a syntax error.

Checklist#

  1. Change every spl fence to js and translate its code with the tables above.
  2. Add await to every model call, tool, human, restrict and codegen.
  3. Turn interpolated strings into template literals and $args/$env into args/env.
  4. Rewrite enums, structs, classes and aliases with the type builder; replace annotations on variables with parse calls where the check matters.
  5. Convert .spl modules to .js modules with export, and make import paths relative to the folder you run spl from.
  6. Run spl workflow.md --check, then record new traces and pins.
