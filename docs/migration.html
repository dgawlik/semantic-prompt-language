Migrating from 2.x

SPL 3.0 has one file format: a .spl file of TypeScript with Markdown comments and --- blocks. Runnable Markdown documents, the block tags of 2.x .spl files, control lines and go() are gone. This guide maps each 2.x construct to its 3.0 form and lists the behavior that changed.

Migration is manual: there is no automatic converter and no compatibility mode.

  • A file that contains 2.x syntax fails with SPL 2.x syntax; see the migration guide. The scanner reports it for a {js}, {ts}, {agent}, {codegen}, {comment} or {lock} tag, for a Markdown code fence, and for the frontmatter keys extension, version and preamble.
  • spl run flow.md is a usage error: 'flow.md': Markdown workflows are no longer executable; SPL 3.0 runs .spl files. See the migration guide.
  • Recorded traces must be recreated, because the source and the runtime changed. Locked workflows cannot be replayed.

Before and after#

A 2.x Markdown workflow:

The same workflow in 3.0:

  • The frontmatter became the file defaults block; extension and version are gone.
  • The heading and the prose moved into a //* ... *// comment.
  • The fences disappeared: their code is the file. It is TypeScript now, so runs and history can carry types.
  • The first blockquote became an ask block. "Save it to @today" is now outputVar: today.
  • The condition that the second blockquote described in words is an if in code, and outputVar: =trend assigns the existing variable.

Files and commands#

SPL 2.x SPL 3.0
workflow.md with frontmatter workflow.spl
workflow.spl with {js} and {agent} tags workflow.spl with code and --- blocks
spl workflow.md, spl workflow.spl spl run workflow.spl
spl workflow.md --check spl check workflow.spl, which now type-checks too
spl workflow.md --pin, then spl workflow.locked.md spl run workflow.spl --trace run.jsonl, twice: a completed trace replays without a model
No equivalent spl compile workflow.spl: an importable TypeScript module
No equivalent spl doc workflow.spl: the workflow as a document
Notebooks in VS Code Removed; use the Run and Debug commands, or spl run --debug

Every other option of spl run is unchanged: --arg, --human, --model, --provider, --cwd, --mcp, --timeout, --trace, --log-level, --silent and --debug.

File structure#

SPL 2.x SPL 3.0
Frontmatter extension and version Removed: the file extension identifies a workflow
Frontmatter model: 'gpt-6-luna' File defaults block with model: gpt-6-luna
Frontmatter preamble: 'Be concise.' File defaults with enforce: Be concise.
Headings and prose; {comment} ... {/comment} A Markdown comment: //* ... *//
A js fence; {js} ... {/js} Code, written directly in the file
A ts fence; {ts} ... {/ts} The same: every file is TypeScript
A fence marked ignore or no-run; {js ignore} An indented or fenced listing inside a Markdown comment
A blockquote; {agent} ... {/agent} An agent block, or an ask block when one answer is all it produces
@CTL(...) at the start of a blockquote; settings in an {agent ...} tag Header keys
@CODEGEN 'description'; {codegen} ... {/codegen} A codegen block
The journal of a locked workflow; {lock} Removed with locked workflows

Instructions#

SPL 2.x SPL 3.0
> Summarize @notes and save it to @summary An ask block with outputVar: summary, or -> @summary in an agent block
"Save to @name", -> @name as a convention the agent followed -> @name is syntax: it declares the output, and an agent may save only declared outputs
@validate[Invoice] save to @invoice ->[Invoice] @invoice in an agent block; outputType: Invoice in an ask block
typedef('Reviews', list(Review)), then @validate[Reviews] The type is an expression: ->[List(Review)] @reviews
@CTL(model='gpt-6-luna', reasoning='high') model: gpt-6-luna and reasoning: high
@CTL(restrict={fs: ['./src'], exec: ['git']}) restrict: { fs: ./src, exec: git }
@CTL(enforce='Be concise', forbid='guessing') enforce: Be concise and forbid: guessing
@success and @fail in a blockquote success() and fail() in code, after the block has saved what they need
The agent tools success, fail and restrict Removed; use code and the restrict header key
@CODEGEN 'Define double(value)' A codegen block: Double a number -> @double(value: number): number
@env.NAME, @args Unchanged
@readFile: a library function as a reference Not needed: the exact tools are always available to an agent

Behavior differences#

  • Types are checked. spl check runs the TypeScript compiler; --check only compiled the code. spl run still erases types without checking them.
  • Normal scoping. 2.x had one shared scope with REPL rules. Now a const cannot be reassigned or redeclared, a name declared inside an if body is not visible after it, and a variable must be declared before a block can assign it with =name.
  • Outputs are declared. A 2.x agent could create any variable by saving it. Now a block declares its outputs, they are typed, and saving anything else stops the block.
  • Agents reach only what the block references. 2.x sent an overview of every shared variable with each blockquote. Now the prompt lists the block's inputs and outputs, and the agent can load and call only the names the instruction mentions.
  • Ask blocks are new. A block without mode is one model call without tools, with the referenced values inlined as JSON. Use it where a 2.x blockquote only produced one answer.
  • Model output is converted. 2.x validated strictly; 3.0 passes answers and saved values to Type.coerce, which accepts numeric strings, JSON text and similar near misses.
  • Agents correct invalid saves. A value that does not fit goes back to the agent up to twice per output instead of stopping the block at once. A missing output fails the block.
  • Reasoning defaults to medium for ask, as it already did for agents; with seed, temperature or topP it defaults to none. 2.x ask had no default reasoning.
  • No preamble. Nothing is prepended to prompts for the whole file unless you write enforce or forbid in the file defaults.
  • Imports resolve from the file. 2.x resolved imports against the working directory. Paths given to tools and restrict still resolve against --cwd.
  • A .spl file is a module. export is allowed, another .spl file can import it, and its default export is the workflow.
  • Generated code is cached without a trace. A codegen block always saves its functions beside the workflow, keyed by its text.
  • Failure payloads changed slightly. source is now a file path and appears only when the failure is in another file; source_version is gone. A failure of a block reports the line of its opening ---.
  • Stepping and state logs follow the code. --debug stops before each block and each top-level statement. State logs cover top-level variables and the outputs of nested blocks; changes to locals inside functions are no longer reported.
  • Locked workflows are gone. --pin and *.locked.* files are removed. A trace gives the same guarantee: a completed trace replays without models, tools or prompts.
  • Notebooks are gone from the VS Code extension, together with support for Markdown workflows.

Editor#

The VS Code extension no longer treats Markdown files as workflows and no longer has notebooks. For .spl files it colors Markdown comments, block headers and instructions, reports TypeScript diagnostics, completes and shows hovers, completes @name inside blocks, and has Run and Debug commands that open a terminal. See Getting started.

Checklist#

  1. Rename workflow.md to workflow.spl. Turn the frontmatter into a file defaults block and the prose into //* ... *// comments.
  2. Remove the fences and tags around code. Add types where they help, and fix what spl check reports.
  3. Rewrite each blockquote or {agent} block as a --- block. Move @CTL settings into the header, declare what the block produces with outputVar or -> @name, and replace @validate[Type] with outputType or ->[Type].
  4. Replace control lines and go() with TypeScript if, while and loops, and move @success and @fail into code.
  5. Replace think() with ask() and a reasoning level.
  6. Rename the types: uppercase names, object to Dict, enumOf to Enum.
  7. Make import paths relative to the file that contains them.
  8. Run spl check workflow.spl, then spl run workflow.spl --trace run.jsonl to record a new trace.
