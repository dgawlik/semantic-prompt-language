Reference

CLI & runtime

The interpreter runs one script file to completion. It prints the result on stdout, logs on stderr and reports the outcome through its exit code.

Usage


spl <script.spl> [--log-level error|info|debug] [--silent] [--model <id>]
                 [--store <file.json> | --store-module <module>] [--backend copilot|mock]
                 [--timeout <s>] [--seed <n>] [--cwd <dir>] [--check]

From a checkout use node dist/cli.js or npx file:./lang. The package installs two equivalent binaries: spl and spl-lang. Exactly one script file is expected.

Output streams & exit codes

stdout

The value of success: strings raw, everything else as pretty-printed JSON. On an uncaught failure: the failure payload.

stderr

Logs, log() output, syntax errors, and for every LLM call the effective model, reasoning effort, temperature and seed.

Exit codeMeaning
0Success.
1Uncaught script failure.
2Syntax or usage error.
70Internal error in the interpreter.

Logging

LevelShows
errorErrors only (for example a variable store that could not be saved).
info (default)Warnings, one line per LLM call with its effective parameters and duration, think{show=True} reasoning, log() messages.
debugEverything above plus the full assembled prompt and the raw response of every call, tool invocations, caught failures and active restrictions.

spl script.spl --silent                    # result only
spl script.spl --log-level debug 2> run.log   # keep the full transcript, pipe the result

Variable store

Scripts can keep state between runs. --store vars.json loads top-level variables from the file at start and writes them back at exit — also on failure. Functions are not persisted. The file must contain a JSON object; writes are atomic (temp file + rename).


spl examples/journal.spl --store journal.json

Custom stores

--store-module ./mystore.mjs plugs in your own persistence. The module exports createStore() (or a default export of that shape) returning an object with load() and save(vars):


import fs from 'node:fs';

export function createStore() {
  const file = './state.json';
  return {
    load() { return fs.existsSync(file) ? JSON.parse(fs.readFileSync(file, 'utf8')) : {}; },
    save(vars) { fs.writeFileSync(file, JSON.stringify(vars)); },
  };
}
⚠️
Synchronous interface

load() and save() are synchronous, so a store must complete its I/O before returning. createStore() itself may be async. save() receives plain JSON-compatible values (vars), never functions.

Backends

copilot

The default. Each LLM call opens a fresh session through the GitHub Copilot SDK with a system message that frames the model as the execution engine of a script, exposing exactly four tools — read_file, write_file, web_fetch, shell — implemented by the SPL runtime so that restrictions apply. Any other permission request is denied. Authenticate with gh auth login.

mock

Offline and deterministic: answers mock: <prompt tail> (or a {"response": …} JSON object for fmt='object'). Use it to syntax-check flows, exercise retry logic, and in CI.

Reproducibility

Control flow, arithmetic and interpolation are deterministic. For LLM calls reproducibility is best effort:

  • The runtime requests temperature=0 and the --seed. The Copilot SDK currently exposes neither setting, so the values cannot be applied; the log line of every call says exactly that.
  • think levels map to the SDK reasoning effort. If the selected model does not support it, a warning is logged and the model default is used.
  • Guard against variance with assert and fmt='object'; see retry patterns.
