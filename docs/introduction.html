  • Code is TypeScript on Node.js. The library is already in scope, so ask, Struct, writeFile and markdown need no import. Type annotations are erased when the file runs and checked by spl check.
  • //* ... *// is a Markdown comment. It is commentary for readers, and spl doc turns it into the prose of the generated documentation.
  • The first --- block has no instruction, so it sets file defaults: the model and guidance for every model call in the file.
  • Struct and Enum describe the data a model must return. Descriptions are written for the model to read. ask(prompt, { schema: Card, repairs: 1 }) converts each answer to a Card and allows one repair attempt.
  • The second --- block is an instruction for an agent. @cards is an input the agent reads with a tool, and ->[Card] @hardest is an output it must save. After the block, hardest is an ordinary typed constant.
  • writeFile is an exact tool. It never calls a model and obeys restrictions.

Three additions to TypeScript#

Everything in a .spl file is TypeScript except three things.

Syntax Meaning
//* ... *// A Markdown comment: prose for readers and for spl doc
--- ... --- A block: an optional header of key: value lines, then an instruction for a model
@name, ->[Type] @name Inside a block: a reference to a variable, and an output the block declares

A block has one of three modes. An ask block is one prompt and one model call. An agent block lets the model act with tools until it has saved every output. A codegen block generates functions.

Generate reusable functions#

A codegen block asks the model for JavaScript functions and declares them as typed constants. Later code calls them like any other function. In code, await codegen(description) does the same and returns the function.

Types the model can read#

Types are ordinary values built with library functions. They check data, convert what a model sends into JavaScript objects and render the JSON Schema that the model receives, including any descriptions you attach.

Union(Float, Int) accepts either number. .methods({...}) makes converted answers objects with methods, so person.toString() works on the model's output. outputType: Person gives the block's output the TypeScript type of Person. See Types.

Why SPL?#

  1. Short loops. One file, run directly with spl run. spl check type-checks it without a model, and --trace run.jsonl resumes recorded work and replays completed runs.
  2. Plain TypeScript where it matters. Control flow, arithmetic and I/O are native code on Node.js, with the standard library and your own modules one import away.
  3. Prompts without string plumbing. An instruction is plain text between two --- lines. @name passes a value in and ->[Type] @name takes a typed value out.
  4. Guards you can see. Types and assert check data; restrict limits what tools and agents may touch. Prompt guidance (enforce, forbid) is kept separate from validation.
  5. Readable. Inputs, prompts, checks and outputs sit in one file, top to bottom, and spl doc renders it as a document.

How a run works#

  1. The scanner turns the file into TypeScript: comments become blank lines and each block becomes a call on the lines it occupied. Syntax errors stop the run before anything executes.
  2. Node.js erases the type annotations and the result runs as an ES module with top-level await.
  3. Code runs top to bottom. ask() and agent() call the official OpenAI, Anthropic and Google clients, one fresh conversation per call.
  4. An ask block sends its instruction with the referenced values as JSON and converts the answer to its output type. An agent block gives the model tools to read its inputs, call the functions it mentions, use files, the web and the shell, and save its outputs.
  5. success(value) ends the run and prints the value on stdout. Logs go to stderr. An uncaught failure prints a JSON payload and exits with code 1.

Non-goals#

  • A custom programming language. Workflow code is TypeScript. The Markdown workflows and the block tags of SPL 2.x are gone.
  • A sandbox. restrict governs the library's tools, agents and MCP servers, not the Node.js APIs that your own code calls.
  • Reproducible model output. Use a trace to replay a recorded run.
