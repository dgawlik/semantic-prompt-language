> SPL
The problem
The gap between a prompt and a process

A clever prompt isn't
a reliable workflow.

A model can interpret the messy parts. The surrounding process still needs exact rules.

01

Instructions are
not checks.

"Return valid data" is a request. A schema and an arithmetic assertion are executable tests.

02

Reasoning is not
permission.

Drafting an action and executing it should have visible, separately controlled boundaries.

03

A good answer is
not a regression test.

Live model output varies. Teams need a way to revisit recorded answers while changing code and guards.

The design opportunity: keep model judgment flexible without making control flow, validation, and I/O equally probabilistic.

> Extract the invoice in @document.
> @validate[Invoice] @retries[2] save to @invoice

```spl
let computed = 0
for line in invoice.lines {
    computed += line.quantity * line.unit_price
}
assert abs(computed - invoice.subtotal) < 0.01
assert abs(invoice.subtotal + invoice.tax
    - invoice.total) < 0.01
restrict './out/invoices' {
    write_file('./out/invoices/{invoice.number}.json',
        json_stringify(invoice, 2))
}
success invoice
```

> SPL
Control model
Keep guidance and guarantees separate

Make the boundary visible.

Use model instructions for intent. Use runtime mechanisms for enforceable checks.

fmt / schema / assert

Validate the result

Strict output parsing, JSON Schema, and exact business-rule checks before downstream work.

ask / think / agent

Separate generation from action

ask and think have no tools. Agent-enabled work can act within active restrictions.

restrict fs / net / exec / mcp

Scope tool access

Bound folders, hosts, executables, and MCP tools. Nested restrictions can only narrow access.

human / @HUMAN / checkpoint

Reserve decisions for people

Pause, publish the question, and resume with the answer without repeating completed calls.

Honest boundaries: restrictions are opt-in, not an OS sandbox. Prompt guidance is not validation. Failures do not roll back earlier actions.

Iteration loop
Iterate on logic without another live model call

Record the answer.
Revisit the checks.

Capture

Run with a trace

Save model requests, raw answers, and failures to a local JSONL trace.

→
Refine

Edit code and guards

Change downstream logic while preserving matching model requests.

→
Replay

Test recorded answers

Rerun against the trace without contacting Copilot or MCP servers.

$ spl flow.md --trace run.jsonl
$ spl flow.md --replay run.jsonl --silent
Replay is not a dry run: explicit file, shell, and web calls still execute. Agent actions are not recreated. Changed model requests fail exact matching. Keep traces private.
